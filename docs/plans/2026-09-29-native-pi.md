# Native Pi 0.99 migration

## Outcome

Audit all 25 packages and adopt stable native Pi APIs where they improve the existing product. Preserve custom capabilities that do not have native equivalents. Target the latest stable release verified on 2026-09-29: Pi 0.99.1.

Luke explicitly waived the Herdr requirement for this task on 2026-09-29. Work remains isolated in a normal Git worktree; signed commits, PRs, testing, CI/review remediation, and merge gates still apply. Canonical main has owner-created untracked files that must remain untouched.

## Work

1. Upgrade the root Pi AI/coding-agent/TUI development dependencies and lockfile. Normalize direct provider streams in the OpenRouter benchmark on every request, preserving later tool turns.
2. Fix notification ownership after runtime replacement and handle successful RPC prompts that are consumed without starting an agent run. Use structured prompt sections and final-settlement cleanup where appropriate.
3. Adopt accurate native tool namespaces/annotations and useful output schemas/structured results. Preserve human-readable content, images, cancellation, permission gates, and public direct-tool names/defaults. Mark genuine failures with native error results without losing paid usage.
4. Use the host's configured provider runtime for nested model calls. Keep config/auth semantics and improve nested-tool error attribution.
5. Add real host contract tests for structured results, nested calls, lifecycle replacement, and current RPC semantics. Update package documentation and tool skills.

## Keep

- Multi-agent workflows/subagents: codemode does not provide child budgets, worktrees, backends, replay, or background run ownership.
- Background terminals: native bash is blocking and has no session-scoped asynchronous manager.
- fd/rg: native find/grep do not preserve all filtering, multiline, smart-case, partial-I/O, or binary-provisioning semantics.
- Graphiti client: native MCP registration does not provide tool execution from off-turn event/timer contexts.
- REST integrations and browser/CDP clients: native MCP parity has not been established. Document native MCP/OAuth as an alternative, not an automatic configuration migration.
- Native TUI/dialog/markdown APIs already used correctly by ask-user, dashboard, and file-links. Do not churn supported theme helpers merely for novelty.
- Pure shared HTTP/auth/config libraries unless an applicable host API replaces actual custom code without changing standalone use.
- Host-provided dependency peer ranges remain `*`, following Pi packaging guidance. Document the supported host version separately.

## Verification

Run `npm run check` after each edit cycle and `npm run pack:check` before shipping. Baseline audit on a disposable 0.99.1 snapshot: 1,023 unit tests passed, 9 skipped; 20 entrypoints/72 tools loaded; all 25 packages packed; three type errors in the direct-stream benchmark.

Required regressions:

- Normalized benchmark system/tool declarations plus all prior assistant/tool-result turns.
- One dispatch binding per live runtime; teardown/replacement binds a new API and never delivers through stale context.
- Handled RPC prompts terminate explicitly without waiting for a nonexistent settled event; started/queued/legacy responses remain valid.
- Structured output matches declared schemas, contains useful data rather than only rendering metadata, and preserves text/image content and errors.
- Nested native tool calls preserve permissions, cancellation, parent attribution, and usage without duplicate counting.
- Prompt sections compose with custom prompts; one-shot thinking survives retries and restores only after final settlement.
- Background processes and queued notifications are cleaned up on shutdown/reload.

Package loading and mocks do not substitute for live runtime lifecycle tests. Avoid credential/service mutation during tests. Any live/network tests need narrowly scoped read-only fixtures or explicit authorization.
